Zheungyuan Rentals — consolidated whatsapp-web.js fix
Date: 2026-08-13

This is intentionally NOT another server.js workaround.

Root cause confirmed:
- The current app installs whatsapp-web.js "latest".
- npm latest is 1.34.7.
- whatsapp-web.js 1.34.7 has a known upstream regression with current
  WhatsApp Web 2.3000.104xxx where Client.getChats() can throw "r: r".
- Upstream PR #201850 (commit 5b6bb00) fixes this exact failure but is still
  open/unreleased.
- The current upstream main branch still contains the broken Promise.all/
  _serialized implementation, so switching from npm "latest" to main would
  not fix it.

Files to replace/add in GitHub:

1. Replace reader/package.json
2. Replace reader/Dockerfile
3. Add reader/patches/wwebjs-pr-201850.patch

Do NOT replace reader/server.js for this update.
Your existing QR/session, label UI and Sync Tenants button remain unchanged.

What this update does:
- Pins whatsapp-web.js to 1.34.7 instead of "latest".
- Pins the other direct reader dependencies too.
- Applies the exact upstream PR #201850 patch during the Railway Docker build.
- Verifies the patch actually exists before the image is allowed to deploy.
- Keeps the persistent WhatsApp LocalAuth volume unchanged.

Expected Railway build log:
- npm install completes
- patching file src/util/Injected/Utils.js
- Docker build passes the grep verification
- reader starts
- WhatsApp ready

After deployment:
1. Open the reader homepage.
2. Confirm Status = Connected.
3. Click Sync Tenants.
4. Send ChatGPT the JSON result.

If the Docker build fails at the patch step, stop there and send the build log.
That is preferable to deploying another silently broken reader.
