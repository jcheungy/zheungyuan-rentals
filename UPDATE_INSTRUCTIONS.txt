Why this supersedes the earlier consolidated package:
The phone still lists the Railway browser as a linked device, and Railway logs
show "WhatsApp authenticated" but never "WhatsApp ready". That confirms the
persistent session is valid and the volume is working; the remaining blocker is
the upstream restored-session ready-state bug.

I checked both upstream fixes carefully:
- PR #201850 fixes Client.getChats() -> "r: r"
- PR #201853 fixes authenticated/restored sessions that remain stuck without
  surfacing "ready"
- BOTH PRs were authored against the SAME exact upstream base commit:
  942d236a11ad68807308b058303ba5256915979c
- They modify different files, so they do not conflict:
  #201850 -> src/util/Injected/Utils.js
  #201853 -> src/Client.js

This build therefore uses that exact upstream base commit and applies BOTH exact
upstream patches. This avoids trying to apply a main-branch patch onto the older
published npm source by accident.
